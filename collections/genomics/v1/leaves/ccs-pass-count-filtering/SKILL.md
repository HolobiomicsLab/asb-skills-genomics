# ccs-pass-count-filtering

## Summary

Collects per-CCS-read subread pass counts from PacBio movie BAMs and restricts downstream PAIso-seq poly(A) tail analysis to circular consensus reads supported by ≥10 passes, ensuring the base-calling accuracy needed to trust non-adenosine (U/G/C) residues called inside poly(A) tail bodies.

## When to use

Use when processing PacBio PAIso-seq CCS BAMs where non-A residues within poly(A) tails must be called reliably and per-read subread pass counts need to gate which CCS reads enter tail-length and residue analysis.

## When NOT to use

- Input is short-read Illumina data (e.g. from the discontinued Genome Analyzer II used by PAL-seq), where no circular consensus pass counts exist to filter on.
- The analysis goal is isoform clustering or de novo transcript discovery with IsoSeq3/IsoSeq tools rather than per-read poly(A) tail residue analysis, which uses its own deduplication (UMI/barcode-based) logic.
- CCS reads were produced with polishing and rich QVs at very high pass depth such that a ≥10-pass floor is trivially satisfied and adds no accuracy benefit while discarding reads.

## Inputs

- PacBio movie subreads BAM (movieX.subreads.bam)
- Circular consensus sequence BAM (movieX.ccs.bam) generated by ccs v3.4.1

## Outputs

- ccs.pass.txt — per-CCS-read pass-count table produced by GetCCSpass.pl
- Filtered set of high-pass (≥10) CCS reads passed into poly(A) tail length and non-A residue calling via run.pl

## How to apply

Generate CCS reads from the movie subread BAM with ccs (version 3.4.1, e.g. with --richQVs or the paper's --min_passes 1 --min_predicted_accuracy 0.9 settings), then run the GetCCSpass.pl script from the GV_oocyte_PAIsoSeqAnalysis repository on the CCS BAM to write a per-read pass-count table (ccs.pass.txt). When launching the pipeline (perl run.pl --ccs sample.out.fasta --sample sampleName --species mm10 --minimap2_index Mus_musculus.mmi --minimap2_thread 10 --pass ccs.pass.txt), supply this pass file so only reads with ≥10 passes are retained. The ≥10-pass threshold is the rationale-carrying decision point: circular consensus accuracy rises with the number of subread passes, and internal U, G, and C calls in poly(A) tails are only credible above it. Reads failing the threshold are excluded before poly(A) tail calling (≥15 nt clipped sequence, ≥5 continuous adenosines, non-A residues <50% and <20 in count) and before aggregating per-gene non-A ratios across replicates.

## Related tools

- **ccs** (Generates circular consensus sequence reads from subreads (version 3.4.1) whose per-read pass counts will be tallied and filtered) — https://github.com/PacificBiosciences/IsoSeq3
- **GetCCSpass.pl** (Perl script in the PAIso-seq analysis pipeline that extracts per-CCS-read pass counts from the CCS BAM into ccs.pass.txt, consumed by run.pl via --pass) — github.com/niehu2018/GV_oocyte_PAIsoSeqAnalysis

## Examples

```
./scripts/GetCCSpass.pl movieX.ccs.bam >ccs.pass.txt && perl run.pl --ccs sample.out.fasta --sample sampleName --species mm10 --minimap2_index Mus_musculus.mmi --minimap2_thread 10 --pass ccs.pass.txt
```

## Evaluation signals

- ccs.pass.txt contains one entry per CCS read from the movie BAM, with pass counts parseable by run.pl's --pass argument.
- All CCS reads surviving into the poly(A) tail / non-A residue table have a pass number ≥10.
- The fraction of transcripts with internal U/G/C residues in the filtered output matches the reported 17% in mouse GV oocytes (Fig. 2c-level validation).
- Per-gene non-A ratios computed from pass-filtered reads correlate across sequencing replicates, as reported in the paper.
- Reads failing the pass threshold appear in the pipeline log (run.log) as excluded rather than contributing to tail-length calls.

## Limitations

- PacBio coverage is limited by cost (about 5 dollars per 1-K reads on the Sequel instrument, ~1000× the Illumina per-read cost), so a ≥10-pass floor can substantially reduce usable reads.
- Replicate correlation of per-gene non-A ratios is expected to improve only with deeper sequencing; current pass-filtered coverage limits precision.
- PAIso-seq cannot accurately quantify non-A modifications at the very last 3′-end base, so pass filtering alone does not fix terminal residue bias.
