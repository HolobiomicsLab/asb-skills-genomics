# tool-runtime-comparison-analysis

## Summary

Benchmark the wall-clock runtime of uTR against TRF and RepeatMasker on the 48 synthetic mosaic tandem repeat datasets, and verify that uTR is faster in most cases while its runtime grows with sequencing error rate and average mosaic TR length (Fig. 1C/1D trends).

## When to use

Use when comparing per-read wall-clock execution times of mosaic tandem repeat decomposition tools (uTR, TRF, RepeatMasker) across synthetic datasets varying TR length and error rate.

## When NOT to use

- The goal is accuracy evaluation of mosaic TR decomposition rather than runtime — use check_uTR/accuracy_uTR.txt style scoring instead
- Input data are real long reads (e.g. realdata/realdata.fasta) without known truth sets, so controlled per-dataset timing comparisons across error rates and TR lengths are not meaningful
- Units longer than 20 nt must be detected, since uTR automatically estimates units of 20 nt or less and mTR would be required instead

## Inputs

- 48 synthetic mosaic tandem repeat FASTA datasets generated by gendata (m,n ranges 2-20 to 2-500, 1000 instances per setting, varying sequencing error rates)
- uTR executable built from https://github.com/morisUtokyo/uTR
- TRF executable
- RepeatMasker configured with HMMER (-e hmmer)

## Outputs

- runtime_comparison.csv with a timing row for each synthetic dataset, including error rate and average TR length columns
- Per-read wall-clock times emitted by uTR -t
- Recorded execution times for TRF and RepeatMasker runs

## How to apply

Compile the benchmark codes in test_public (gendata, check_uTR, parse_RepeatMasker, check_RepeatMasker) with make.sh, then generate the 48 synthetic mosaic TR datasets with gendata, varying m and n ranges (e.g. 2-20 up to 2-500, 1000 instances per setting) and the sequencing error rate. Run uTR on each dataset with the -t flag so it emits the wall-clock time to process each read, keeping the default maximum dissimilarity ratio of 0.3 (-r 0.3). Time TRF on the same dataset files, and run RepeatMasker as 'repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file' recording its execution time. Aggregate per-dataset timings into a single table with error-rate and average TR length columns, then check that uTR is faster than both baselines on the majority of datasets and that uTR runtime increases with error rate and average TR length.

## Related tools

- **uTR** (Mosaic tandem repeat decomposer whose per-read wall-clock time is collected with the -t flag at default -r 0.3) — https://github.com/morisUtokyo/uTR
- **TRF** (Baseline tandem repeat finder timed on the same synthetic dataset files for runtime comparison)
- **RepeatMasker** (Baseline run as 'repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file' and timed on the same datasets)
- **gendata** (Generates the simulated mosaic TR datasets with controlled m,n ranges and error rates used for timing) — https://github.com/morisUtokyo/uTR

## Examples

```
uTR -f TR_file.fasta -o annotated.fasta -t -r 0.3
```

## Evaluation signals

- runtime_comparison.csv contains a timing row for every one of the 48 synthetic datasets
- uTR wall-clock time is lower than both TRF and RepeatMasker on the majority of datasets
- uTR runtime trend increases monotonically (or near-monotonically) with sequencing error rate, reproducing the Fig. 1C trend
- uTR runtime trend increases with average mosaic TR length (m,n ranges 2-20 up to 2-500), reproducing the Fig. 1D trend
- uTR runs use the default maximum dissimilarity ratio of 0.3 (MAX_DIS_RATIO_DEFAULT in uTR.h) so timings are comparable to the published setting

## Limitations

- The comparison is on synthetic mosaic TRs; conclusions may not transfer to real reads
- uTR's version number is not stated in the paper, so exact reproducibility of timings may vary
- The -t flag reports per-read wall-clock time only; system-level variance across TRF/RepeatMasker invocations is not normalized
- For complex patterns, alternate uTR modes (-y, -z) change decomposition behavior and were not part of the default timing setup

## Evidence

- [abstract] uTR is faster than TRF and RepeatMasker in most cases: "and uTR is faster than TRF and RepeatMasker in most cases."
- [readme] uTR -t emits wall-clock time per read: "-t : Output the wall clock time to process each read in the input fasta file."
- [methods] RepeatMasker timing command: "repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file"
- [methods] Default dissimilarity ratio 0.3: "-r : Give a maximum threshold on the mismatch ratio between the representaitve unit and a tandem repeat of the unit."
