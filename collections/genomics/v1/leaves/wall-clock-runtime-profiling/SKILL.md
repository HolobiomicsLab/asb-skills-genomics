# wall-clock-runtime-profiling

## Summary

Benchmarking procedure for measuring per-read wall-clock runtime of uTR against TRF and RepeatMasker on synthetic mosaic tandem repeat datasets, to reproduce the paper's finding that uTR is faster in most cases and that runtime grows with sequencing error rate and average mosaic TR length (Fig. 1C/1D trends).

## When to use

Use when comparing computational cost of tandem repeat decomposition tools (uTR vs TRF vs RepeatMasker) on simulated FASTA datasets and characterizing how error rate and average TR length drive uTR runtime.

## When NOT to use

- The goal is prediction accuracy rather than runtime — use the check_uTR / check_RepeatMasker accuracy workflow (accuracy_uTR.txt, accuracy_RepeatMasker.txt) instead.
- The data are long repeat units (>20 nt) that require mTR preprocessing, not the short-unit runtime benchmark addressed here.
- Real long-read data is the target — the timing benchmark is defined on synthetic gendata datasets, not realdata.fasta.

## Inputs

- Synthetic mosaic tandem repeat FASTA datasets generated by gendata (m, n ranges such as 2-20 to 2-500, 1000 instances per setting, varied sequencing error rates)
- Compiled uTR, TRF, and RepeatMasker executables
- RepeatMasker run configuration: -e hmmer -noint -pa 4 -div 0 -xsmall

## Outputs

- Per-read wall-clock times emitted by uTR via the -t flag
- Aggregated runtime table (e.g. runtime_comparison.csv) with a timing row per dataset plus error-rate and average-TR-length columns
- Runtime trends showing uTR faster than TRF and RepeatMasker on the majority of datasets

## How to apply

Compile the benchmark codes in test_public (gendata, check_uTR, parse_RepeatMasker, check_RepeatMasker) with make.sh, then generate synthetic mosaic TR datasets with gendata while varying the m and n ranges (e.g. 2-20 up to 2-500, 1000 instances per setting) and the sequence error rate. Run uTR on each dataset with the -t flag so the wall-clock time to process each read is emitted, keeping the default maximum dissimilarity ratio of 0.3 (set by MAX_DIS_RATIO_DEFAULT in uTR.h, or explicitly -r 0.3). Run TRF on the same dataset files and RepeatMasker with 'repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file', recording each tool's execution time. Aggregate per-dataset wall-clock times into a table with error-rate and average-TR-length columns so runtime scaling trends can be verified.

## Related tools

- **uTR** (Primary tool under benchmark; run with -t to emit wall-clock time per read and default -r 0.3 dissimilarity threshold) — https://github.com/morisUtokyo/uTR
- **TRF** (Baseline tandem repeat finder whose execution time is recorded on the same dataset files)
- **RepeatMasker** (Baseline run as 'repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file'; its execution time is compared with uTR)
- **gendata** (Generates the synthetic mosaic TR datasets with controlled m, n ranges and sequencing error rates used for timing) — https://github.com/morisUtokyo/uTR

## Examples

```
uTR -f $TR_file -o annotated.fasta -t
```

## Evaluation signals

- runtime_comparison.csv contains a timing row for every synthetic dataset generated by gendata
- uTR wall-clock time is lower than both TRF and RepeatMasker on the majority of datasets
- uTR runtime increases monotonically with sequencing error rate (Fig. 1C trend)
- uTR runtime increases as the average mosaic TR length grows with larger m and n ranges, e.g. 2-20 up to 2-500 (Fig. 1D trend)
- uTR was run with the default dissimilarity ratio 0.3 (MAX_DIS_RATIO_DEFAULT in uTR.h) so timings are comparable to the paper's settings

## Limitations

- uTR's advantage is 'in most cases' — some datasets may show a faster baseline, so majority-level, not per-dataset, superiority is expected.
- Runtime conclusions depend on the uTR version used; the article does not state a version number.
- Wall-clock timings from the -t flag are per-read and machine-dependent, so absolute values are not portable across hardware.
