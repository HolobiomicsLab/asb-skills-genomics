# vcf-variant-record-formatting

## Summary

Formats structural variants detected in nanopore-derived viral consensus genomes into per-sample variant record files, following the VirDetector pipeline's structured output conventions (VCF-style records alongside reference-assembly outputs in results.txt).

## When to use

Use when a Nextflow-based virus surveillance pipeline has reconstructed viral consensus genomes (reference-based or hybrid assembly) and structural variants must be detected with Sniffles2 and persisted as per-sample variant record files.

## When NOT to use

- No consensus genome has been reconstructed yet (e.g. input is still raw FASTQ/FAST5/POD5 or only preprocessed reads) — structural variant calling operates on assembled consensus genomes
- Only FASTA files were supplied as input without additional samples — these are consumed from the alignment step onwards, so per-sample variant detection workflows may not apply as expected
- The goal is SNP/small-variant calling on read alignments rather than structural variants of assembled genomes

## Inputs

- Viral consensus genome sequences per sample (generated by reference-based or automated hybrid assembly within VirDetector)
- Reference sequence in FASTA format placed in the resources folder (params.ref)
- nextflow.config file used to enable/disable individual pipeline steps

## Outputs

- Per-sample VCF-style structural variant record files in the pipeline's structured output directories
- Updated results.txt summarizing detected structural variants alongside reference-assembly outputs

## How to apply

Load each sample's viral consensus genome sequence produced by the reference-based or hybrid assembly step of VirDetector. Run the structural-variant caller Sniffles2 on each consensus genome against the reference to identify structural variants relative to that reference. Write the detected variants per sample into a VCF-style variant record file, placing it in the pipeline's structured output directories so it sits alongside the other reference-assembly outputs. Finally verify that a variant record file exists for every processed sample and that the detected variants are summarized in results.txt; this step is optional and is controlled via the nextflow.config parameter switches, which are the only file edited to change pipeline behavior.

## Examples

```
nextflow run main.nf
```

## Evaluation signals

- A variant record file exists for each processed sample
- Detected structural variants are summarized alongside the other reference-assembly outputs in results.txt
- Variant record files follow the pipeline's structured output directories
- The step can be toggled via the nextflow.config parameter switches (params.* = "true"/"false"), so disabling it yields no variant records
- The full pipeline executes end-to-end with 'nextflow run main.nf' (excluding basecalling) without errors

## Limitations

- Structural-variant detection is an optional downstream step; if all steps are disabled, samples are only preprocessed and trimmed, and no variant records are produced
- Detection operates on assembled consensus genomes relative to a user-supplied reference sequence; accuracy depends on the chosen reference in FASTA format (params.ref)
- VirDetector was developed and tested under Ubuntu 22.04 LTS; other operating systems require the Docker installation
