# sra-dataset-download-and-preprocessing

## Summary

Retrieves the exact real RNA-Seq read sets used in the rnaSPAdes benchmark (8 NCBI SRA runs from Human, Human large, Mouse, Worm, Corn, and Arabidopsis) plus the RSEM-simulated Human reads, so that assembler evaluations use the same inputs as the published benchmarks.

## When to use

Use when a de novo transcriptome-assembly benchmark must start from the paper's exact read sets — you have SRA accession lists (e.g. Human SRR5133163, Mouse SRX648736) or need the RSEM-simulated Human RNA-Seq data from Supplementary Section S3.

## When NOT to use

- The reads are already available locally in FASTQ/BAM — skip download and feed them straight to the assembler
- The target is metatranscriptome assembly — the paper states the approach 'was initially designed for RNA-Seq data obtained from a single organism' and metatranscriptome evaluation is unaddressed future work
- Long-read (PacBio/Oxford Nanopore) transcriptome data — the paper notes their high error rate prevents using output reads directly as complete transcripts, and these accessions are Illumina data

## Inputs

- NCBI SRA accession identifiers (SRR1957703, SRR1957706, SRX648736, SRR1560107, SRR1588569, SRR5344669, SRR5344670)
- RSEM simulator command lines from Supplementary Section S3 (for the simulated Human dataset)
- Raw paired-end Illumina RNA-Seq reads expected in FASTQ format

## Outputs

- FASTQ read files for the 8 real datasets (paired-end, one pair per accession)
- Simulated Human RNA-Seq read set generated by RSEM

## How to apply

Map each benchmark dataset to its SRA accession: Human SRR5133163; Human large SRR1957703/SRR1957706; Mouse SRX648736; Worm SRR1560107; Corn SRR1588569; Arabidopsis SRR5344669/SRR5344670; download the paired reads in FASTQ format with the SRA toolkit. For the simulated Human dataset, do not download from SRA — instead run the RSEM read simulator with the exact command lines given in Supplementary Section S3. Keep reads untrimmed and raw because rnaSPAdes deliberately excludes external error correction (the BayesHammer module is skipped in the rnaSPAdes pipeline), and rnaQUAST/Kallisto quantification are then run directly on the downloaded FASTQs. Validate the retrieval by checking that each dataset yields the paired-end files expected by the assemblers (rnaSPAdes, SPAdes, Trinity, RNA-Bloom, etc.) that consume them downstream.

## Related tools

- **rnaSPAdes** (Downstream de novo transcriptome assembler consuming the downloaded FASTQ reads) — github.com/ablab/spades
- **SPAdes** (Baseline assembler run (single-cell mode, k=21,33,55) on the same retrieved datasets for comparison) — github.com/ablab/spades
- **RSEM** (Read simulator used to generate the simulated Human RNA-Seq dataset per Supplementary Section S3)
- **rnaQUAST** (Reference-based evaluator run on assemblies of the retrieved reads)

## Evaluation signals

- Each of the 7 real SRA accessions resolves to paired-end FASTQ files matching the dataset-to-accession map (e.g. Human large = SRR1957703 + SRR1957706)
- The simulated Human dataset is produced by the RSEM command lines from Supplementary Section S3, not by an SRA download
- Assembling the retrieved reads with rnaSPAdes and evaluating with rnaQUAST reproduces reported anchors (e.g. rnaSPAdes 309 misassemblies on the simulated Human dataset)
- Kallisto gene-detection normalization over the retrieved datasets yields cross-dataset means matching rnaSPAdes 0.500, Trinity 0.438, RNA-Bloom 0.406, SPAdes 0.397

## Limitations

- The Human large and Corn SS datasets were noted as exceptions where rnaSPAdes did not have fewer misassemblies, so cross-dataset behavior is not uniform
- rnaSPAdes excludes the BayesHammer read error correction module, so no external error-correction step should be inserted into preprocessing
- No single assembler is the absolute leader across all quality metrics and all datasets, so dataset retrieval alone does not determine assembler choice
