# tandem-repeat-unit-decomposition

## Summary

A skill for decomposing DNA strings into mosaic tandem repeats composed of different repeat units using the uTR algorithm, which greedily selects repeat units and then computes an optimal partial-match decomposition. It outperforms TRF and RepeatMasker, especially on complex mosaic TRs with three or more series of units.

## When to use

Use when long-read (e.g. PacBio) FASTA sequences contain mosaic tandem repeats with multiple different repeat units that standard tools like TRF or RepeatMasker fail to decompose correctly.

## When NOT to use

- Input is a single simple (non-mosaic) tandem repeat with one unit — TRF or RepeatMasker suffice and mosaic-unit selection is unnecessary
- The mismatch ratio between the representative unit and the tandem repeat exceeds the -r threshold (default 0.3) — uTR outputs no tandem repeat at all
- The goal is inspecting per-unit substitutions/indels in a known decomposition rather than computing it — vTR, not uTR, outputs variant units from an already-estimated pattern

## Inputs

- Input FASTA file of long reads containing mosaic tandem repeats (e.g. realdata/realdata.fasta)
- Optional representative unit string via -u (units >20 nt estimated beforehand with mTR)
- Optional locus information string (e.g. chr8:118366813-118366928) via -l
- Simulated ground-truth datasets generated by gendata in test_public (e.g. (AC)i(AG)j with occurrence counts 10-200, substitution error rates 0-15%)

## Outputs

- Output FASTA annotated with '#Info (length, haplotypes, dissimilarity ratio) #Pat <unit>count... #Decomp [...]' entries
- Accuracy reports accuracy_uTR.txt and accuracy_RepeatMasker.txt with per-condition correct/total pattern counts and average pattern lengths

## How to apply

First, pre-cluster similar reads with cTR (max Levenshtein distance 0.01x average read length) to reduce computation time, and estimate units longer than 20 nt with mTR; uTR itself auto-estimates units of length 20 nt or less unless -u supplies a representative unit. Run uTR with -f for the input FASTA and -o for annotated output; the greedy unit-selection loop initializes U empty and iteratively adds the candidate unit (rotations permitted, e.g. CAG/AGC) that minimizes the extended penalty sum(|u|+o(u)) over selected units plus residual decomposition length, terminating when no candidate reduces it. The final stage computes the optimal concatenation of selected units that partially matches the input string via the wraparound dynamic programming string decomposer or the Myers-Miller O(|S|*sum|u|) approximate regular-expression matching, then applies tie-breaking conventions (-y prefers more complex patterns with fewer mismatches; -z optimizes alignment score minus unit count to favor longer units). Control the dissimilarity threshold with -r (default 0.3, MAX_DIS_RATIO_DEFAULT in uTR.h); output annotations take the form '#Info (171,125,0.129) #Pat <CAG>19<CCG>38 #Decomp [...]'.

- Running example S=ACCGACCGACCG with U={ACCG} must yield decomposition (ACCG)3 with penalty 7 (greedy loop selects ACCG over AC/CG at penalty 11 and CGAC at penalty 10)
- The ambiguity example must yield two optimal decompositions (AG)2(AGGG)2(AG)2(AGGG)2 and (AGAGAGGGAGGG)2 with equal penalty 14
- Benchmark row '2 500' in accuracy_uTR.txt must show 998/1000 correct predictions at average pattern length 1011
- Annotation format check: each output record carries '#Info (length, haplotypes, dissimilarity ratio)', '#Pat', and optionally '#Decomp' tags; dissimilarity must be at or below the -r threshold (default 0.3)
- Accuracy should match the Fig. 1A/1B trend: uTR matches or exceeds TRF and RepeatMasker, especially for mosaic TRs with three or more series of units, with accuracy dropping as sequencing error rises to 15%

## Limitations

- uTR automatically estimates tandem repeat units only up to 20 nt; longer units require mTR, and reads with repeats must be pre-clustered with cTR to keep runtime manageable
- No tandem repeat is output when the mismatch ratio to the representative unit exceeds the threshold (-r, default 0.3)
- The uTR version number is not stated in the article
- Prediction accuracy drops as sequencing error rate increases (up to 15% in the benchmark)
