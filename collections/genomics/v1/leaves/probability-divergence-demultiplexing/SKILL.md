# probability-divergence-demultiplexing

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Demultiplex corrupted DNA barcodes from high-error-rate nanopore reads using PRO's two-stage approach: extract the noisy barcode by aligning flanking sequences with edlib, then assign each barcode by maximum probability divergence (PRO-dex), a probabilistic divergence measure that outperformed Guppy by 4.31% on large PRO-designed kits.

## When to use

Use when nanopore (ONT) FASTQ/FASTA reads contain barcodes embedded in adapter-flanking-barcode-flanking-insert library structures and you must assign reads to samples despite ONT-level insertion/deletion/substitution errors.

## When NOT to use

- PacBio sequencing data — the authors note PRO 'can be employed for both ONT and PacBio sequencing data; however, no tests on PacBio data have been performed yet'
- Barcode kits whose flanking sequences are similar to the barcodes themselves (as with ONT kits B1–B3), where PRO cannot accurately extract the corrupted barcode and Guppy performs better
- Reads lacking the expected adapters-flanking-barcode-flanking-insert library structure with known flanking sequences, since barcode extraction depends on edlib alignment of the flanking sequences

## Inputs

- Directory containing FASTQ/FASTA files of nanopore sequencing reads (e.g. generated by deepsimulator 1.5)
- FASTQ file of the flanking sequences used in library preparation (passed via -f)
- Reference barcode set (e.g. the PRO-designed 24-mer kit of 2,292 barcodes or an ONT kit cfg file)

## Outputs

- Read-to-barcode assignments in the 'dex_result' output folder
- Demultiplexing accuracy metric when ground-truth barcode identities are available (reported value: 98.29% on the size-2,922 kit)

## How to apply

Set up the environment with Anaconda3, Python 3.7+, edlib 1.3.9 and tqdm, then clone PRO from github.com/rztongr/PRO. Run PRO's demultiplexer with -i pointing to the directory of nanopore sequencing files, -f to a FASTQ file of the flanking sequences used in library preparation, -o to an output directory, and -t for the number of threads. PRO first aligns the flanking sequences (narrowing the alignment window, e.g. sequence′[35:77] and sequence′[35+startf:120]) with edlib to extract the corrupted barcode from each read, then assigns the read by maximum probability divergence (ProDiv(X,Y)=pmmpdd(13ps)s(14pi)i) among the reference barcodes. Before demultiplexing, set the threshold t by converting the number of errors expected to be correctly demultiplexed into probability divergence, which governs the accepted assignment. Output assignments land in the 'dex_result' folder; validate by comparing assignments against ground-truth barcode identities.

## Evaluation signals

- On the simulated 24-mer barcode set B9, PRO-dex should reach 98.29% demultiplexing accuracy versus 93.98% for Guppy on the same kit
- When the barcode kit size matches an official ONT kit size, PRO's accuracy should be comparable (superior and comparable) to Guppy's
- The output directory must contain the 'dex_result' folder with per-read demultiplexing assignments
- Threshold t must be derived from the expected number of errors converted into probability divergence; assignments exceeding t are rejected
- Flanking-sequence alignment windows must be narrowed (sequence′[35:77] and sequence′[35+startf:120]) before extraction to reduce false extractions

## Limitations

- PRO underperforms Guppy on ONT kits B1, B2, B3 because the flanking sequences are similar to the barcodes and cannot be accurately extracted, and ONT's design strategy does not ensure large probability divergence between barcodes
- No tests on PacBio data have been performed, despite the method being theoretically applicable
- Demultiplexing correctness depends on the threshold t; barcodes with errors beyond the threshold converted into probability divergence may be misassigned
