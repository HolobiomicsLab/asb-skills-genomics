# antimicrobial-resistance-gene-detection

## Summary

Detects acquired antimicrobial resistance genes and chromosomal resistance-conferring point mutations from de novo genome assemblies using Staramr within the NanoGalaxy AMR workflow, and compares the detected gene count against published reference counts (e.g., Li et al.).

## When to use

Use when de novo assemblies from Nanopore long-read sequencing data of bacterial isolates are available and the goal is to detect resistance genes plus chromosomal point mutations and compare counts with published studies.

## When NOT to use

- Input is raw Nanopore FASTQ reads rather than de novo genome assemblies — assembly must be completed upstream in the NanoGalaxy workflow first
- The comparison target is a study that used a different detection scope, since counts are not directly comparable when PointFinder chromosomal point mutations are absent from the reference method
- Short-read (150–300 bp) sequence data is the input, as this toolkit is designed for Nanopore long-read sequencing data analysis

## Inputs

- De novo genome assemblies of bacterial isolates generated by the NanoGalaxy long-read AMR workflow
- Staramr configuration with the PointFinder chromosomal point-mutation database enabled

## Outputs

- Staramr report with resfinder hit tables (acquired resistance genes)
- Staramr pointfinder hit tables (chromosomal resistance-conferring point mutations)
- Tallied total count of detected resistance genes for comparison against Li et al.

## How to apply

Load the de novo genome assemblies generated upstream by the NanoGalaxy AMR long-read workflow. Run Staramr on the assemblies with the PointFinder chromosomal point-mutation database enabled, so that both acquired resistance genes (ResFinder hits) and chromosomal resistance-conferring point mutations are detected. Parse the Staramr output — the resfinder and pointfinder hit tables — to extract the list of detected resistance genes and point mutations. Tally the total number of detected resistance genes and compare with the number reported by Li et al. for the same isolates. The run validates the workflow only if the Staramr report is produced and the detected gene count exceeds the count reported by Li et al., an expected outcome because Staramr additionally includes the PointFinder (chromosomal point mutations) database.

## Related tools

- **Staramr** (Runs ResFinder and PointFinder-based detection of acquired resistance genes and chromosomal resistance-conferring point mutations on the assemblies, producing resfinder and pointfinder hit tables)
- **NanoGalaxy** (Galaxy-based toolkit providing the upstream long-read de novo genome assemblies and the environment in which the AMR analysis use case is executed) — https://github.com/mmiladi/galaxy-nanopore
- **Galaxy** (User-friendly platform hosting the NanoGalaxy tools so the AMR analysis can be performed without programming experience) — https://nanopore.usegalaxy.eu

## Examples

```
docker run -d -p 8080:80 mmiladi/galaxy-nanopore
```

## Evaluation signals

- A Staramr report is successfully produced for every input assembly
- The resfinder and pointfinder hit tables are parseable and enumerate detected resistance genes and point mutations
- The total tally of detected resistance genes exceeds the count reported by Li et al. for the same isolates
- PointFinder hits are present, confirming the chromosomal point-mutation database was enabled (the expected reason for the higher count)
- Assemblies were generated by the upstream NanoGalaxy long-read AMR workflow, matching the provenance used in the article

## Limitations

- The higher gene count vs. Li et al. is attributable to Staramr's inclusion of the PointFinder chromosomal point-mutation database, so the count difference is an expected artifact of database scope, not a superiority claim
- Tool versions are not stated in the paper's discussion — all tools and dependencies are managed via the Conda framework on the Galaxy platform, so exact Staramr/PointFinder database versions must be recorded separately
- Other long-read analysis tools exist or are under development but were deliberately not integrated; the toolkit focuses on the most established and widely used tools
- The Docker-based deployment (mmiladi/galaxy-nanopore) serves Galaxy on port 8080 via a containerized Apache webserver, which must be reachable before the analysis
