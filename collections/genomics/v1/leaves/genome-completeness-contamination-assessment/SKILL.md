# genome-completeness-contamination-assessment

## Summary

Scores candidate metagenomic bins (MAGs) for completeness and contamination using 107 prokaryotic single-copy marker genes (via hmmer), and combines the two into an F1-score per Eq. 4 of SemiBin2 for ranking bins during ensemble DBSCAN clustering of long-read data.

## When to use

Use when candidate bins have been produced from long-read contig embeddings (e.g., per-epsilon DBSCAN outputs in SemiBin2) and each bin must be scored for completeness, contamination, and F1 before greedy ensemble selection.

## When NOT to use

- Binning short-read samples with the standard (non-ensemble) SemiBin2 pipeline, where DBSCAN is run without the multi-epsilon ensemble and greedy selection
- Input is raw reads or unassembled contigs that have not yet been clustered into candidate bins — marker-gene scoring requires bins as input
- Taxonomic annotation of bins is the goal (use CAT/BAT instead); this skill only estimates completeness/contamination

## Inputs

- Candidate bins from DBSCAN runs at 12 epsilon values (0.01–0.55) over SemiBin2 deep-learning contig embeddings
- Long-read contigs used for binning (--sequencing-type=long_read), FASTA
- Trained deep-learning model features (data.csv / data_split.csv)
- Reference set of 107 prokaryotic single-copy marker genes

## Outputs

- Per-bin completeness and contamination estimates from single-copy marker gene counts
- F1 score per bin (Eq. 4) used to rank bins in the greedy Algorithm 1
- Final ensemble bins as gzipped FASTA per bin in output_bins, plus bins_info.tsv and contig_bins.tsv

## How to apply

For each candidate bin generated by DBSCAN at the 12 epsilon values (0.01–0.55) on the learned contig embeddings, detect single-copy marker genes with hmmer against a set of 107 prokaryotic single-copy marker genes. From the marker-gene counts estimate bin completeness (fraction of expected single-copy markers present) and contamination (excess copies of markers), then compute the F1 score per Eq. 4 of the SemiBin2 paper. During ensemble integration (Algorithm 1), iteratively accept the highest-F1 bin whose contamination does not exceed the threshold, sweeping thresholds from 0.1 to 1.0 and removing contigs already assigned to an accepted bin. The rationale is that marker-gene-based scoring gives a principled per-bin quality measure that allows the greedy algorithm to assemble the best possible bin set from per-epsilon candidates, yielding more high-quality bins than any single-epsilon run.

## Related tools

- **SemiBin2** (Runs DBSCAN at 12 epsilon values on learned contig embeddings, scores bins with the 107 single-copy marker genes, and applies the greedy Algorithm 1 for ensemble bin selection) — https://github.com/BigDataBiology/SemiBin/
- **DBSCAN** (Clustering algorithm applied per epsilon value to generate the candidate bin sets that are then scored for completeness/contamination)
- **hmmer** (External dependency used to detect single-copy marker genes for completeness and contamination estimation)

## Examples

```
SemiBin single_easy_bin -i contigs.fasta -b *.bam --sequencing-type=long_read -o output_bins
```

## Evaluation signals

- Each candidate bin has non-empty completeness and contamination values derived from the 107 single-copy marker genes and an F1 score per Eq. 4
- The greedy Algorithm 1 accepts only bins whose contamination does not exceed the current threshold while sweeping 0.1–1.0, and no contig appears in two accepted bins (check contig_bins.tsv)
- The ensemble bin set contains more high-quality bins than any single-epsilon DBSCAN run on the same embeddings
- Output directory contains gzipped FASTA per bin together with bins_info.tsv and contig_bins.tsv
- Relative bin quality is consistent with the paper's report of 13.1–26.3% more high-quality genomes than the second-best long-read binner

## Limitations

- Completeness/contamination estimates depend on marker-gene detection (hmmer), so bins from organisms with divergent or missing marker genes may be mis-scored
- The greedy algorithm's result depends on the contamination threshold sweep (0.1–1.0); a poorly chosen threshold regime can exclude valid bins
- SemiBin operations are probabilistic — running the pipeline twice can return different bins and scores, as noted in the tutorial
