# long-read-assembly-amr-profiling

## Summary

A NanoGalaxy-based workflow that de novo assembles Oxford Nanopore long reads and profiles antimicrobial resistance with Staramr (ResFinder + PointFinder chromosomal point-mutation database), enabling AMR gene counts to be compared against reference studies such as Li et al.

## When to use

Use when the goal is to detect resistance genes and chromosomal point mutations in bacterial isolates from Nanopore long-read data, or to reproduce AMR gene-count comparisons between an assembly-based pipeline and a published study.

## When NOT to use

- Input is raw Nanopore FASTQ that has not yet been assembled — run the upstream NanoGalaxy de novo assembly workflow first
- You need AMR detection limited strictly to acquired genes to match a study's methodology without chromosomal point mutations — disabling PointFinder changes the expected gene-count comparison
- Data are short-read (150–300 bp) rather than Nanopore long reads; this toolkit is focused on long-read analysis of the most established tools for ONT data

## Inputs

- De novo genome assemblies (contigs/FASTA) generated by the NanoGalaxy long-read AMR workflow
- Oxford Nanopore long-read sequencing reads (FASTQ) feeding the upstream assembly
- Staramr configuration with the PointFinder chromosomal point-mutation database enabled

## Outputs

- Staramr summary report
- ResFinder hit table listing detected acquired resistance genes
- PointFinder hit table listing chromosomal resistance-conferring point mutations
- Tallied resistance gene count per isolate for comparison with Li et al.

## How to apply

Start from de novo genome assemblies produced by the upstream NanoGalaxy long-read workflow (NanoGalaxy is a Galaxy toolkit for analysing long-read Oxford Nanopore data, including de novo genome assembly from genomic, metagenomic, and plasmid reads). Run Staramr on the assemblies with the PointFinder chromosomal point-mutation database enabled so that both acquired resistance genes and resistance-conferring chromosomal point mutations are detected. Parse the Staramr output tables — the resfinder hits and pointfinder hits — to extract the detected resistance genes and point mutations, then tally the total gene count. Compare this tally with the count reported by the reference study (Li et al.) for the same isolates; a higher count is expected and is the correct outcome, because Staramr additionally includes the PointFinder chromosomal point-mutation database. The pipeline runs in Galaxy, which handles software dependencies via the Conda framework, so no command-line or programming skills are required.

## Related tools

- **Staramr** (AMR detection engine: scans assemblies with ResFinder for acquired resistance genes and PointFinder for chromosomal point mutations; its resfinder/pointfinder hit tables are the comparison basis against Li et al.)
- **NanoGalaxy** (Galaxy toolkit providing the upstream de novo genome assembly from Nanopore long reads and hosting the AMR use case workflow and its training manual) — https://nanopore.usegalaxy.eu
- **Galaxy** (Platform that hosts NanoGalaxy, manages tool dependencies via Conda, and lets users run the workflow without programming experience) — https://nanopore.usegalaxy.eu

## Examples

```
docker run -d -p 8080:80 mmiladi/galaxy-nanopore
```

## Evaluation signals

- A Staramr summary report is produced for every input assembly (run success criterion)
- Both a resfinder hit table and a pointfinder hit table are returned, confirming PointFinder was enabled
- The tallied resistance gene count exceeds the count reported by Li et al. for the same isolates, reproducing the article's finding
- Detected resistance genes and point mutations can be enumerated explicitly from the parsed hit tables
- Upstream assemblies are genuine de novo Nanopore assemblies (genomic/metagenomic/plasmid reads), not externally supplied short-read assemblies

## Limitations

- The higher resistance gene count relative to Li et al. is expected only because Staramr includes the PointFinder chromosomal point-mutation database; identical counts are not the success criterion
- NanoGalaxy focused on the most established long-read tools; other long-read analysis tools exist or are under development but were not integrated
- Integrated tools were intensively tested for ONT data; tools supporting Pacific Biosciences 'should also work' but are untested in this context
- Supporting data for the article are external (Zenodo, GigaScience GigaDB), so exact isolate inputs must be retrieved separately
