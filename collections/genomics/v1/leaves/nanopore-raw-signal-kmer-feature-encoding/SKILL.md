# nanopore-raw-signal-kmer-feature-encoding

## Summary

Extracts combined per-read features for RedNano m6A detection from Nanopore direct RNA sequencing: a 5-mer sequence channel, a 65-sample rectified raw-current signal window, and basecalling-error features (qual, mis, ins, dele), then feeds them into dual-ResNet encoders with a sigmoid read-level head.

## When to use

Use when resquiggled Nanopore DRS FAST5 signals and basecall alignments are available and per-read k-mer/signal/error features must be encoded and pooled into site-level m6A probabilities.

## When NOT to use

- Input is already an aggregated site-level file (test.features.sort.aggre.tsv); rerunning extraction or read-level feature sorting is redundant
- Only basecalled FASTQ/sequence data are available without raw FAST5 signals or quality/error features — RedNano's dual-branch design requires both k_signals_rect and qual/mis/ins/dele features
- Target sites have fewer than 20 aligned reads, since the site-level aggregation workflow filters them out with the $4>=20 awk criterion

## Inputs

- Single-read FAST5 files resquiggled by tombo (corrected group RawGenomeCorrected_001) in the guppy workspace
- Per-read basecalling-error split files (test.tsv split into tmp/*.txt)
- Reference transcriptome FASTA and transcriptome length file with header (e.g. cc.bed with ID/length columns)
- Pre-trained checkpoint (e.g. models/mil_allspecies_model_states.pt) for the comb_basecall_raw model

## Outputs

- Per-read feature TSV with columns: chrom, pos, alignstrand, loc_in_ref, readname, strand, k_mer, k_signals_rect, qual, mis, ins, dele
- Site-aggregated feature file filtered at coverage >= 20 reads (test.features.sort.aggre.c20.tsv)
- Per-site prediction table with transcript, pos, strand, prob, label columns

## How to apply

Run RedNano's extract_features.py on the tombo-resquiggled FAST5 workspace with -k 5 (5-mer) and -s 65 (65-sample rectified signal window) and the RawGenomeCorrected_001 corrected group, plus per-read basecalling-error files generated by splitting test.tsv. The output is one sample per row with columns chrom, pos, alignstrand, loc_in_ref, readname, strand, k_mer, k_signals_rect, qual, mis, ins, dele. For site-level prediction, sort reads, aggregate features to site level with aggre_features_to_site_level.py, and apply the awk coverage filter $4>=20 before multiple-instance-learning prediction. The 5-mer channel is embedded (embedding_size 4, seq_lens 5) while the 65-sample signal window and error features pass through separate ResNet branches (32/64/128/256 channels) of model_type comb_basecall_raw; a two-hidden-layer FC head (hidden_size 128, dropout 0.5, sigmoid) yields read-level probabilities that are aggregated to site level Pt.

## Examples

```
python scripts/extract_features.py -i /path/to/fast5_guppy/workspace/ -o test/features/ --errors_dir test/tmp/ --corrected_group RawGenomeCorrected_001 -b test/referance.transcript.bed --w_is_dir 1 -k 5 -s 65 -n 30
```

## Evaluation signals

- Extracted feature rows contain exactly the 12 expected columns (chrom, pos, alignstrand, loc_in_ref, readname, strand, k_mer, k_signals_rect, qual, mis, ins, dele)
- Each k_mer field is a 5-mer and each k_signals_rect window contains 65 rectified signal samples (seq_lens 5, signal_lens 65)
- Site-level files are coverage-filtered so every retained row has read count (column 4) >= 20
- predict.py end-to-end run yields a results table whose modification probabilities fall in [0, 1] for every site, consistent with the sigmoid output
- Trained checkpoint is produced in train/ after 50 epochs with patience-5 early stopping (lr 1e-4, weight_decay 1e-5, clip_grad 0.5, batch_size 4)

## Limitations

- Tombo resquiggle must be run against the reference transcript (gene) FASTA, not a genome reference
- Multi-read FAST5 inputs must first be split with ont_fast5_api before downstream processing
- Site-level probability reporting requires the multiple-instance-learning aggregation path and the coverage >= 20 filter; sites below coverage are not scored
