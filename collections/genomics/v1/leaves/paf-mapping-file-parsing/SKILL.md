# paf-mapping-file-parsing

## Summary

Parses and summarizes the labelled PAF file produced by ntLink's mapping mode (Alternate Protocol 1), using Miller (mlr) to compute total mappings, average mapping block length, and average mappings per draft contig as reported in Table 5 of the ntLink Current Protocols article.

## When to use

Use when a labelled PAF file of long-read to contig mappings generated by ntLink with paf=True needs to be counted, aggregated per target contig, or validated against published mapping statistics.

## When NOT to use

- The input is a raw, unlabelled PAF from a different mapper (e.g. minimap2) whose column semantics were not produced by ntLink's paf=True output — field positions and labels differ.
- The goal is scaffolding (Basic Protocols 1–3) or Tigmint-long correction (Alternate Protocol 2), where mappings are consumed by ntLink itself rather than being summarized.
- Quality-filtering or misassembly detection is the goal; this skill only counts and averages, it does not filter or correct.

## Inputs

- Labelled PAF file of long-read to contig mappings produced by ntLink mapping mode (paf=True)
- Expected mapping statistics from Table 5 of the ntLink article (for validation)

## Outputs

- mapping_stats.tsv containing: total number of mappings, average mapping block length, and average number of read mappings per draft contig

## How to apply

Load the labelled ntLink PAF mapping file (the read-to-contig mappings emitted when ntLink mapping mode is run with paf=True) into Miller (mlr) as a delimited/TSV table. Use mlr stats and aggregation verbs to compute the total number of mappings (row count) and the average mapping block length from the query and target start-end coordinate fields of each PAF record. Group records by the target contig identifier and compute the average number of read mappings per draft contig. Write the three statistics (total mappings, average block length, average mappings per contig) to mapping_stats.tsv and validate them against the expected mapping statistics in Table 5 of the article. Rationale: ntLink's minimizer-based mappings are lightweight and intended for downstream applications, so file-format-level counting (rather than full alignment re-analysis) is the sanctioned way to assess mapping output; the ntLink wiki documents the output file formats.

## Examples

```
mlr --tsv count then stats1 mean -f block_length then stats1 mean -f num_mappings -g target_contig ntlink_mappings.paf > mapping_stats.tsv
```

## Evaluation signals

- The three computed statistics in mapping_stats.tsv (total mappings, average block length, average mappings per contig) match the corresponding expected values in Table 5 of the article.
- The total-mappings row count equals the number of PAF records in the input file.
- The average block length is derivable from the query/target start-end coordinate fields of each PAF record (end minus start), so a spot-check of individual records reproduces the aggregate.
- Per-contig groups in the grouping step cover all target contig identifiers present in the PAF, and the average mappings per contig equals total mappings divided by the number of distinct target contigs.

## Limitations

- Validation relies on the published expected values from Table 5; a different draft assembly or read set will not match those numbers.
- The PAF must be the labelled output of ntLink mapping mode (paf=True); the output file format details are documented on the ntLink wiki and must be consulted if column semantics are unclear.
- Miller expects the file as a delimited table (e.g. TSV), so raw column-position-only PAFs need labelling before the aggregation verbs can reference named fields.
