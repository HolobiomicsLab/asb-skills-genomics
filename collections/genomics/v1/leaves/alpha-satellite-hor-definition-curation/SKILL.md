# alpha-satellite-hor-definition-curation

## Summary

Curates alpha-satellite high-order repeat (HOR) definitions from HORmon output (cen*_monomers.fa, cen*_hors.tsv) and scores centromere-bound single-breakend contigs by monomer-decomposition concordance with StringDecomposer, yielding a per-contig HOR match score in [0,1].

## When to use

Use when long-read contigs of single breakend SVs annotated 'Satellite/centr' by RepeatMasker must be scored for consistency with chromosome-specific centromeric HOR structure (canonical vs non-canonical HORs).

## When NOT to use

- The input contigs are not centromeric/satellite (not annotated 'Satellite/centr' by RepeatMasker) — HORmon monomer sets are chromosome-specific and only meaningful for alpha-satellite sequence
- Analyzing canonical two-breakpoint somatic SVs — this skill scores only single breakend contigs whose free end lies in centromeric repeats
- No HORmon-curated monomer/HOR definitions (cen*_monomers.fa, cen*_hors.tsv) exist for the chromosome of interest, since the scoring is defined against these curated files

## Inputs

- Single breakend SV result file from nanomonsv (Contig column of 'High Repeat single breakend SVs')
- RepeatMasker annotation identifying contigs as 'Satellite/centr'
- HORmon final monomer FASTA files (cen*_monomers.fa under monomersFinal directory)
- HORmon curated HOR definition files (cen*_hors.tsv from HORmonHORs directory)
- StringDecomposer 1.1.2 output: final_decomposition.tsv per chromosome monomer file

## Outputs

- Per-contig HOR match scores in hor_match_scores.csv (columns: contig ID, chromosome, HOR match score)
- Qualitative classification of contigs as matching canonical chromosome-specific HORs vs non-canonical HORs (e.g. the 17-mer ABCDEFGHIJKLHIJKL on chromosome X)

## How to apply

Extract contigs of single breakend SVs classified as 'High Repeat single breakend SVs' from the nanomonsv single breakend result file (Contig column), keeping those mostly annotated 'Satellite/centr' by RepeatMasker. Run StringDecomposer version 1.1.2 on each contig against the final monomer FASTA files generated by HORmon (cen*_monomers.fa under the monomersFinal directory) to obtain a final_decomposition.tsv per chromosome monomer file. Read each final_decomposition.tsv line by line and, for each adjacent monomer pair whose pre-/post-relationship matches the curated HOR definitions (cen*_hors.tsv from the HORmonHORs directory), add (<end-pos> - <start-pos>) * <identity> / 100 to a running sum. Divide the summed concordance by the contig length to obtain the HOR match score, and write per-contig scores to hor_match_scores.csv with contig ID, chromosome, and score columns.


## Evaluation signals

- Each HOR match score falls in the valid range 0-1, since summed (end-pos - start-pos) * identity / 100 cannot exceed the contig length
- final_decomposition.tsv is produced for each chromosome monomer file by StringDecomposer 1.1.2 before scoring
- Only adjacent monomer pairs whose pre-/post-relationship is consistent with cen*_hors.tsv contribute to the summed concordance
- hor_match_scores.csv contains the required columns (contig ID, chromosome, HOR match score) with one row per contig
- Resulting scores reproduce the paper's qualitative result: most contigs match canonical chromosome-specific HORs with a minority of non-canonical HORs (e.g. the 17-mer ABCDEFGHIJKLHIJKL on chromosome X)

## Limitations

- The HOR match score depends on the specific curated HORmon definitions; non-canonical HORs such as the 17-mer ABCDEFGHIJKLHIJKL on chromosome X contribute only partially or not at all
- StringDecomposer version 1.1.2 is specified; other versions may change the decomposition output format or scoring behavior
- Only single breakend SVs classified as 'High Repeat single breakend SVs' and mostly 'Satellite/centr' by RepeatMasker are eligible, restricting coverage to contigs with one breakpoint anchored outside the centromere
