# chromosomal-point-mutation-screening

## Summary

Screens de novo bacterial genome assemblies for chromosomal point mutations conferring antimicrobial resistance using Staramr with the PointFinder database enabled, complementing acquired-gene detection so resistance gene counts exceed those from ResFinder-only studies (e.g., Li et al.).

## When to use

Use when comparing AMR gene detection against a published resistance gene count (e.g., Li et al.) and you need chromosomal resistance-conferring point mutations included, given de novo long-read assemblies of bacterial isolates.

## When NOT to use

- Input data are raw Nanopore reads rather than de novo assemblies — this skill operates on assemblies from the upstream AMR workflow
- The goal is to reproduce a ResFinder-only acquired-gene count without chromosomal point mutations — enabling PointFinder will inflate counts relative to such baselines
- Analysis targets eukaryotic or viral genomes where bacterial AMR point-mutation databases do not apply

## Inputs

- De novo genome assemblies (FASTA) of bacterial isolates generated by the NanoGalaxy long-read (Oxford Nanopore) assembly workflow
- Staramr PointFinder chromosomal point-mutation database (enabled within the Staramr Galaxy tool)

## Outputs

- Staramr report with resfinder hit table (acquired resistance genes)
- Staramr pointfinder hit table (chromosomal resistance-conferring point mutations)
- Tallied resistance gene count for comparison against Li et al.

## How to apply

Load the de novo genome assemblies produced by the upstream NanoGalaxy AMR long-read workflow (from Oxford Nanopore reads) into Galaxy. Run Staramr on the assemblies with the PointFinder chromosomal point-mutation database enabled so that both acquired resistance genes (ResFinder hits) and chromosomal point mutations (PointFinder hits) are detected. Parse the separate resfinder and pointfinder hit tables from the Staramr output to extract the detected resistance genes and mutations. Tally the total number of detected resistance determinants and compare against the count reported by Li et al. for the same isolates; a higher count is expected because Staramr adds the PointFinder chromosomal mutation database on top of acquired-gene detection. Validation: the run succeeds when a Staramr report is produced and the detected resistance gene count exceeds the Li et al. count, reproducing the article's finding.

## Related tools

- **Staramr** (Primary detection tool; run on assemblies with PointFinder chromosomal point-mutation database enabled to detect both acquired resistance genes and chromosomal point mutations)
- **NanoGalaxy** (Galaxy-based toolkit providing the upstream long-read de novo genome assembly workflow whose assemblies feed the Staramr AMR analysis) — https://github.com/mmiladi/galaxy-nanopore

## Examples

```
docker run -d -p 8080:80 mmiladi/galaxy-nanopore  # then in Galaxy: upload de novo assembly FASTA -> run Staramr with PointFinder chromosomal point-mutation database enabled
```

## Evaluation signals

- A Staramr report is produced for every input assembly without errors
- The pointfinder hit table is non-empty for isolates known to carry chromosomal resistance mutations
- The total tallied resistance gene count (resfinder + pointfinder hits) exceeds the count reported by Li et al. for the same isolates, reproducing the article's finding
- Both resfinder and pointfinder hit tables are parsed separately so acquired genes and point mutations are not conflated in the tally
- Assemblies derive from the same isolates analysed by Li et al., making the comparison like-for-like

## Limitations

- The higher resistance gene count versus ResFinder-only studies is expected and attributable to the included PointFinder chromosomal point-mutation database, not to superior assembly sensitivity
- NanoGalaxy integrated tools were intensively tested for ONT (Oxford Nanopore) data; results on other platforms are untested
- The skill depends on assembly quality from the upstream NanoGalaxy long-read workflow — assembly errors can cause missed or false point-mutation calls
