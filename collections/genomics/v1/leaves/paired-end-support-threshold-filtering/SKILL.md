# paired-end-support-threshold-filtering

## Summary

Down-filters a consensus structural variant (SV) call set — here the 315-call fission yeast set accepted by at least two callers — by removing calls with low paired-end support, breakpoints in MQ=0 regions, and overlaps with annotated long terminal repeats, prior to manual read-alignment inspection. Implemented with the SURVIVOR filter module from the Jeffares et al. (2017) S. pombe SV pipeline.

## When to use

Use when a consensus VCF of SV calls (merged across callers with SURVIVOR) must be down-filtered before manual curation — e.g. dropping calls with low paired-end support or breakpoints in low-complexity or annotated LTR regions.

## When NOT to use

- The input is raw caller output rather than a merged consensus set — the article filters the post-SURVIVOR-merge set (SVs detected by at least two callers), not individual caller VCFs.
- The goal is maximum SV sensitivity rather than specificity — the authors explicitly prioritized high specificity over detecting all SVs, so this aggressive filtering will drop true calls.
- The variants are translocations or inversions requiring genotyping re-examination — the article excluded these from re-examination because they were more challenging to accurately genotype.

## Inputs

- Consensus SV call set VCF produced by SURVIVOR merge (the 315-call set supported by at least two callers)
- BED of low-complexity / MQ=0 regions to ignore (e.g. generated by SURVIVOR bincov)
- Annotation of previously annotated long terminal repeats (LTRs)

## Outputs

- filtered_svs.vcf — VCF of surviving SV calls, free of calls with paired-end support <=10, breakpoints in MQ=0 regions, and LTR-overlapping breakpoints, ready for manual read-alignment vetting

## How to apply

Start from the consensus SV call VCF produced by the SURVIVOR merge step — in the article this is the 315-call set accepted by at least two of Delly, Lumpy, Pindel and cn.MOPs. Run the SURVIVOR filter module, which 'filters a vcf file based on size and/or regions to ignore', setting the paired-end support threshold to <=10 reads so low-support calls are removed. To handle mapping-quality artefacts, use SURVIVOR bincov to produce a bed of coverage bins and drop SVs whose breakpoints fall in MQ=0 regions. Intersect SV breakpoints with the annotation of previously annotated long terminal repeats (LTRs) and remove any call overlapping an LTR or low-complexity region. Write surviving calls to filtered_svs.vcf for downstream manual inspection of read alignments; the article prioritized high specificity (correctness of inferred SVs) over high sensitivity, so the goal of this filtering stage is precision, not call recovery.

## Related tools

- **SURVIVOR** (Provides the 'filter' module that removes VCF SV calls based on size and/or regions to ignore, plus 'bincov' to bin coverage to a bed for filtering SVs in low-MQ regions; the merge module produces the consensus input set.) — https://github.com/fritzsedlazeck/SURVIVOR

## Evaluation signals

- filtered_svs.vcf exists and parses as a valid VCF
- No surviving call has paired-end support <=10 reads
- No surviving SV breakpoint falls in an MQ=0 region
- No surviving SV breakpoint overlaps an annotated long terminal repeat (LTR)
- Call count drops from the 315-call consensus set (final curated set was 113 SVs: 23 deletions, 64 duplications, 11 inversions, 15 translocations), consistent with specificity-first filtering

## Limitations

- The pipeline prioritized high specificity (correctness of the inferred SV) over high sensitivity, so not all SVs present in the data are recovered after this filtering stage.
- Thresholds such as the <=10 paired-end support cutoff were optimized in the context of short-read data from four callers (Delly, Lumpy, Pindel, cn.MOPs); other datasets may need recalibration.
- Filtering removes LTR-overlapping and low-complexity breakpoints wholesale, which can discard genuine SVs at repetitive loci; remaining calls still require manual visual inspection of read alignments.
