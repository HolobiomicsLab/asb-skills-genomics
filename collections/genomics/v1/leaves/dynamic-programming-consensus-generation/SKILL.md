# dynamic-programming-consensus-generation

## Summary

PECAT-style haplotype-aware consensus generation: build a partial-order alignment (POA) graph from raw long reads, score supporting reads against the template read at heterozygous dominant branches, re-weight selected same-haplotype supports, and emit a corrected consensus read by dynamic programming.

## When to use

Use when correcting long noisy reads (Nanopore R9/R10 or PacBio CLR) from a diploid genome while preserving heterozygote alleles that a vanilla POA consensus would collapse away.

## When NOT to use

- Data are Nanopore duplex or PacBio HiFi reads — the paper reports the method achieves only mediocre performance on these high-accuracy data
- The goal is a consensus/variant call on an existing assembly rather than error-corrected reads — Medaka pileup-based consensus or Clair3 SNP calling is the appropriate alternative
- Heterozygosity rate is very low — the method cannot distinguish small sequencing errors from heterozygote alleles in such regions

## Inputs

- Raw long noisy reads from Nanopore R9, Nanopore R10 or PacBio CLR sequencing (reads.fasta.gz)
- Filled PECAT config file (e.g. genome_size=1500000, prep_output_coverage, corr_rd2rd_options, corr_iterate_number)
- Candidate supporting-read overlaps generated by minimap2 read-to-read alignment

## Outputs

- Haplotype-aware corrected reads written as a FASTA file at the 1-correct output location (S1/1-correct/corrected_reads.fasta)

## How to apply

Extract the prep_output_coverage longest raw reads (e.g. 80X; all reads if below 80X) from the input FASTA/FASTQ, and align reads to each other with minimap2 ('-x ava-pb' for PacBio CLR reads) to obtain candidate supporting-read overlaps for POA graph construction. For each template read, build its POA graph and detect heterozygous positions as dominant parallel branches; score each supporting read +1 when it passes through the same branch as the template and -1 otherwise, then histogram scores and keep only high-scoring reads as same-haplotype supports. Generate the consensus path by dynamic programming, penalizing each mismatch of a supporting read by P_c = max(0.4^r, 0.3)*W_c where W_c is the re-weighting factor of the selected support, and iterate corr_iterate_number rounds. The rationale is that restricting evidence to same-haplotype supports retains heterozygote alleles while sequencing errors, which are not shared by same-haplotype reads, are corrected away.

## Related tools

- **PECAT** (Implements the POA-based haplotype-aware error correction; run via the 'pecat.pl correct' entry point) — https://github.com/lemene/PECAT
- **minimap2** (Computes candidate read-to-read overlaps ('-x ava-pb' for PacBio CLR, '-x ava-ont' for Nanopore) that seed the POA graphs) — https://github.com/lh3/minimap2

## Examples

```
./pecat.pl correct config_file
```

## Evaluation signals

- The corrected-reads FASTA file exists at S1/1-correct/corrected_reads.fasta after 'pecat.pl correct' completes
- Heterozygous SNP alleles present in the raw reads are retained in corrected reads rather than collapsed to the majority allele
- Per-read support scores form a bimodal histogram; only high-scoring (same-haplotype) supports are re-weighted in the consensus
- Correction is run corr_iterate_number rounds with mismatch penalty P_c = max(0.4^r, 0.3)*W_c, and downstream assembly yields haplotype-specific contigs (e.g. phase block NG50 of 59.4/58.0 Mb for HG002 Nanopore R10)
- Assemblies can be evaluated with Pomoxis reference-based assessment and SV calls checked with hapdiff

## Limitations

- SNP calling accuracy from corrected reads alone is low in low-heterozygosity-rate regions
- The correction may not distinguish small sequencing errors from heterozygote alleles in very low heterozygosity regions
- PECAT needs higher data coverage for a high-quality phased assembly
