# Long-read SNV calling

## Summary

Calls single-nucleotide variants from haplotype-aware long-read alignments within the ccsmethphase pipeline: Clair3 is applied to pbmm2-merged ccsmeth modBAMs using its HiFi model, and only PASS SNVs are retained for subsequent WhatsHap phasing.

## When to use

Use when PacBio HiFi/CCS reads (e.g. hifi BAM or ccsmeth modBAM) must be converted to a phased variant layer so reads can be haplotagged for allele-specific methylation analysis.

## When NOT to use

- Input reads are Illumina short reads or nanopore data — Clair3's HiFi model and this pipeline target PacBio HiFi/CCS reads only.
- The goal is methylation calling itself — use ccsmeth read-level/site-level models; SNV calling is only the intermediate haplotyping layer of ccsmethphase.
- High-confidence external VCFs (e.g. GIAB truth sets) are available for phasing — WhatsHap can phase against those directly without de novo Clair3 calling.

## Inputs

- pbmm2-aligned/merged ccsmeth modBAM (modified bam) of PacBio HiFi reads
- Reference genome FASTA (e.g. chr20_demo.fa)
- Input sheet (Group_ID, Sample_ID, Type='hifi', Path) describing samples
- Clair3 HiFi model supplied with the pipeline

## Outputs

- clair3_called directory: SNVs generated by Clair3 (VCF)
- SNV_PASS-filtered VCF used as input to WhatsHap phasing
- Phased downstream artifacts whose names embed SNV_PASS (e.g. ...merged_size1.SNV_PASS_whatshap.bam, ...SNV_PASS_whatshap.freq.aggregate.*.bed)

## How to apply

Inside the ccsmethphase Nextflow pipeline, take the pbmm2-merged ccsmeth modBAM (e.g. G1.HG002_demo.hifi.ccsmeth.modbam.pbmm2.merged_size1) as the alignment input and the reference genome (e.g. chr20_demo.fa) and run Clair3 with its HiFi model to call SNVs. Filter the Clair3 output to keep only variants marked PASS (the SNV_PASS filter) before downstream use. The PASS SNVs are then phased with WhatsHap, which is what enables haplotype tagging of the methylation-bearing modBAM reads. Correct application is judged by the presence of a clair3_called directory of SNV VCFs and downstream file names embedding the SNV_PASS token, such as ...SNV_PASS_whatshap.bam. Rationale: methylation phasing depends on high-quality germline SNVs from HiFi reads; retaining only PASS calls avoids phasing reads on low-confidence variants.

## Evaluation signals

- A clair3_called directory exists in ccsmethphase_results/<dsname> containing SNV VCFs generated by Clair3.
- Downstream file names embed the SNV_PASS token, e.g. G1.HG002_demo.hifi.ccsmeth.modbam.pbmm2.merged_size1.SNV_PASS_whatshap.bam, confirming only PASS variants propagated.
- A whatshap_phased directory with phased SNV VCFs exists, proving the SNV calls were consumable by WhatsHap.
- The phased output VCF and haplotagged modBAM are consistent with each other and follow the documented ccsmethphase naming pattern.
- SNVs are limited to the reference contigs permitted by the --include_all_ctgs setting (chr1-22,X,Y when false).

## Limitations

- Only symmetric CpG methylation is the pipeline's target; SNV calling here serves methylation phasing and does not address other DNA modifications such as 6mA or non-CpG 5mC.
- Variant quality is restricted to PASS calls; low-confidence Clair3 variants are discarded and may leave reads unphased.
- By default only chr1-22,X,Y contigs are included (--include_all_ctgs false), so variants on other contigs are not called/propagated unless the flag is set to true.
