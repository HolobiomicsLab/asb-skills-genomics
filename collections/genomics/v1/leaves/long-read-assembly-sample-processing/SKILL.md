# long-read-assembly-sample-processing

## Summary

Prepares per-sample low-coverage (~5×) HiFi assemblies from HiFiCCL-Hifiasm and Hifiasm — renaming sequences for uniqueness, pooling with CHM13 (v1.0) — as input for minigraph pangenome graph construction and bubble-consistency evaluation against the HPRC reference graph.

## When to use

Use when you have per-sample long-read assemblies (e.g., ~5× HiFi human assemblies from HiFiCCL-Hifiasm or Hifiasm) that must be pooled, made name-unique, and fed into minigraph pangenome graph construction for bubble-level precision/recall evaluation.

## When NOT to use

- Input reads are high-coverage HiFi (well above ~5×–10×), where standard de novo assembly without reference-guided chromosome-by-chromosome binning suffices
- Goal is direct SV calling from reads rather than assembly-based pangenome graph construction and bubble-consistency evaluation
- Genomes with high genetic diversity such as plants — the article tested only two plant samples and broader plant evaluation was not performed

## Inputs

- Downsampled HiFi (~5×) per-sample assemblies from HiFiCCL-Hifiasm (45 human samples)
- Downsampled HiFi (~5×) per-sample assemblies from Hifiasm (45 human samples)
- GRCh38 reference genome sequence
- CHM13 (v1.0) sequence
- Bubble BED file from the pangenome graph constructed by minigraph from the HPRC release

## Outputs

- Name-unique, alphabetically sorted multi-sample assembly FASTA per assembler variant
- Pangenome graph (GFA) per assembler variant from minigraph
- Bubble-region BED file per graph, emitted by gfatools
- bubble_consistency_metrics.csv with interval-wise Precision, Recall, and F1

## How to apply

Collect the downsampled HiFi (5×) assemblies of the 45 human samples generated by both HiFiCCL-Hifiasm and Hifiasm, renaming each sequence to ensure uniqueness across all assemblies. For each assembler variant, build the pangenome graph with minigraph (github.com/lh3/minigraph) using GRCh38 as the reference and supplying CHM13 (v1.0) plus the 45 per-sample assemblies as input, sorted alphabetically. Run gfatools (gfa2bed) on each constructed graph to identify bubble regions and emit them as a BED file. Compare each BED against the bubble BED from the minigraph graph built from the HPRC release, classifying bubbles with >80% overlap as TP, non-overlapping predicted bubbles as FP, and reference bubbles lacking 80% overlap as FN. Compute Precision = TP/(TP+FP), Recall = TP/(TP+FN), and F1 = 2×Precision×Recall/(Precision+Recall) per interval and write all interval-wise metrics to bubble_consistency_metrics.csv.

## Examples

```
./gfatools gfa2bed -m HiFiCCL-Hifiasm_graph.gfa > HiFiCCL-Hifiasm_graph.bed
```

## Evaluation signals

- Both assembler-variant graphs yield positive precision and recall at all thresholds; expected reported values are ~0.9067 precision / ~0.6974 recall at the >0% bubble-coverage threshold and ~0.8435 precision / ~0.5399 recall at >50%, with HiFiCCL-Hifiasm_graph consistently outperforming Hifiasm_graph
- All sequence names are unique across the 45 pooled per-sample assemblies before minigraph ingestion
- TP/FP/FN classification uses the 80% overlap rule against the HPRC-release bubble BED (predicted bubble >80% overlap = TP; non-overlapping prediction = FP; reference bubble lacking 80% overlap = FN)
- F1 values equal 2×Precision×Recall/(Precision+Recall) for every interval and assembler variant
- All interval-wise metrics are written to bubble_consistency_metrics.csv

## Limitations

- At ~5× coverage many genomic regions remain missing, so completeness gaps persist in the assemblies feeding the graph
- No version numbers are stated for HiFiCCL, Hifiasm, or RagTag, complicating exact reproduction
- Bubble evaluation is reduced to an 80%-overlap binary TP/FP/FN classification at multiple coverage thresholds, which may not capture partial bubble concordance
