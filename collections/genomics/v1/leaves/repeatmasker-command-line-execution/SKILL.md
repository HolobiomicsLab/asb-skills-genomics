# repeatmasker-command-line-execution

## Summary

Runs RepeatMasker as a baseline tandem repeat annotator on simulated mosaic tandem repeat (TR) datasets from the uTR benchmark, using the paper's exact HMMER-based invocation, and parses/checks its output for accuracy and runtime comparison against uTR and TRF.

## When to use

Use when benchmarking uTR (or another mosaic tandem repeat decomposer) against RepeatMasker on simulated mosaic TR fasta datasets, or when collecting RepeatMasker wall-clock execution times for a runtime comparison table.

## When NOT to use

- The goal is to decompose mosaic TRs themselves — RepeatMasker is only a baseline comparator and, per the paper, often fails to properly decompose mosaic TRs
- The input is real long-read data without a correct answer pattern, where the test_public accuracy-checking workflow (check_RepeatMasker) does not apply

## Inputs

- Simulated mosaic tandem repeat dataset in FASTA format ($TR_file) generated by gendata in test_public
- Correct answer mosaic repeat patterns from gendata for accuracy checking

## Outputs

- RepeatMasker annotation output for each simulated dataset
- Parsed RepeatMasker predictions (from parse_RepeatMasker) for accuracy scoring
- Accuracy report (accuracy_RepeatMasker.txt via test.sh)
- Per-dataset RepeatMasker execution times for the runtime comparison table

## How to apply

Compile the benchmark codes in the uTR repo's test_public directory (gendata, check_uTR, parse_RepeatMasker, check_RepeatMasker) using make.sh. Feed each simulated dataset (named $TR_file, generated by gendata with m,n ranges such as 2-20 up to 2-500 and 1000 instances per setting) into RepeatMasker with the command 'repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file', where -e hmmer selects the cross_match-free HMMER engine, -noint restricts to non-intersecting TR matches, -pa 4 uses 4 parallel processes, -div 0 sets divergence to 0, and -xsmall applies the x-small sensitivity threshold. Parse RepeatMasker's output with parse_RepeatMasker so it can be scored by check_RepeatMasker against the correct answer mosaic patterns. For the runtime comparison, record RepeatMasker's execution time per dataset and aggregate into a timing table alongside uTR's per-read wall-clock times (uTR run with the -t flag and default -r 0.3 dissimilarity threshold) to verify the paper's finding that uTR is faster in most cases.

## Related tools

- **RepeatMasker** (Baseline tandem repeat annotation tool invoked with -e hmmer -noint -pa 4 -div 0 -xsmall on the simulated datasets)
- **parse_RepeatMasker** (Parses RepeatMasker output so predictions can be scored against correct answer patterns) — https://github.com/morisUtokyo/uTR
- **check_RepeatMasker** (Checks RepeatMasker prediction accuracy against the simulated ground-truth mosaic repeat patterns) — https://github.com/morisUtokyo/uTR
- **uTR** (Comparator tool whose prediction accuracy and runtime (via -t flag, default -r 0.3) are compared against RepeatMasker) — https://github.com/morisUtokyo/uTR

## Examples

```
repeatmasker -e hmmer -noint -pa 4 -div 0 -xsmall $TR_file
```

## Evaluation signals

- accuracy_RepeatMasker.txt contains a row per (m,n) setting showing how many of 1000 patterns RepeatMasker predicted correctly, parallel to accuracy_uTR.txt
- The runtime comparison table contains a timing row for each of the 48 synthetic datasets, with RepeatMasker times aggregated alongside uTR and TRF
- uTR is faster than RepeatMasker on the majority of datasets, and runtime increases with sequencing error rate and average mosaic TR length (Fig. 1C/1D trends)
- RepeatMasker was invoked with exactly '-e hmmer -noint -pa 4 -div 0 -xsmall' as specified in the paper's methods

## Limitations

- RepeatMasker is not designed to solve the mosaic TR problem and often fails to properly decompose mosaic TRs, especially for more complex patterns
- The benchmark accuracy results depend on the simulated dataset settings (m and n ranges, 1000 instances per setting, error rate); uTR itself predicts 998/1000 correctly only in the m,n=2-500 setting
